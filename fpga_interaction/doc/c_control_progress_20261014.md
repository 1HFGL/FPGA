# C 演奏控制阶段成果与接口（2026-10-14）

本轮在本地 `fpga_interaction`、`fpga_a` 和 `fpga_ab_sim` 修改并验证。
队友 2026-10-09 的 PLAN.md 作为需求和评审资料使用，没有改动该微信文件。
本成果发布于 `codex/c-play-control` 独立分支；没有修改正式引脚约束或下载开发板。

## 实现的行为

| 情况 | 当前行为 |
|---|---|
| 本地与 PC 弹同音 | 按来源 ID + 原始音符匹配，不合并不同来源，不再按音高兜底松音或更新表情 |
| 同一来源的同音仍按住，再发 note-on | 重用当前声部、更新力度/音色并递增起音序号；A 重新进入起音，即使 gate 一直为高 |
| 松键后有尾音，再按相同音 | 有空闲声部时另开新声部，保留旧尾音；旧尾音仍计入占用 |
| 满载 | 优先抢占最早起音的已松键声部，其次最早起音的仍按住声部；任何抢占均产生新起音序号 |
| 长时间运行或频繁重触发 | 用声部之间的先后关系保存起音次序，不依赖时钟时间戳，不存在原先约 85.9 秒的回绕问题 |
| 按住时切八度 | 已发音保持原音符；松键使用按下时保存的音符；新按键使用当前八度 |
| 开延音后松键 | 标记物理键已松，gate 保持；旧尾音可以与新起音并存 |
| 关闭延音 | 只释放已经松键的声部，仍按住的声音不受影响 |
| 某输入来源断线/故障 | 提供带来源掩码的清理命令，释放该组声音且绕过延音，不直接打断其他来源 |
| 旧释放完成信号到达 | 开启代次校验后，仅接受与当前起音序号匹配的完成反馈，不误回收新声部 |
| 13 键同时变化、下游暂时繁忙 | 每键四项队列 + 默认 64 项事件 FIFO，保存按下/松开顺序和按下时的参数；轮转选择避免低编号键长期占先 |
| 队列超限 | input_fault 锁存、停止该输入流、发出本地来源组释放命令；正常尾音保留，复位后恢复 |

延音状态控制已完成，但本地 A 仍是原四种基本波形和普通 ADSR。
其保持段为非零电平；计划要求的“钢琴自然衰减”仍需队友的钢琴包络/音色实现。
本轮没有把普通持续音伪称为真实钢琴延音。

## 对接合同

### 1. 事件与来源

- `event_valid && event_ready` 在时钟上升沿接受事件；忙时发送端保持 valid 和字段。
- `event_type=1` 起音，`0` 松音；匹配键为 `(event_source_id,event_note)`。
- 表情事件同样严格匹配该二元组；不存在未知来源按音高兜底。
- 默认 SOURCE_WIDTH=5。来源 0..12 对应本地琴键，13..15 留给同一本地组，16..31 留给 PC 组。
  同一 PC 来源 ID 可以同时持有不同音符。触摸扩展若需更多独立 ID，应扩大 SOURCE_WIDTH 并重新分配来源组。
- 新顶层或事件合并器必须保存来源；不能把本地和 PC 同音编码成同一个来源 + 音符。

### 2. C→A 起音与 A→C 完成

- 新增 `voice_trigger_id_flat`：每声部 16 位，位段为 `[voice_index*16 +: 16]`。
  每次起音/重触发/抢占递增，保持稳定至下次起音；A 在音频采样使能处比较已消费序号。
- 保留 `voice_gate`；新增 `voice_key_down`，区分真正按住与延音保持。gate 不承担独立起音标记。
- A 已在本地 `synth_engine`、`adsr_envelope` 接入该序号并重新启动包络。
- A 返回 `release_done` 及 `release_trigger_id_flat`。后者表示 A 已消费的起音代次。
- 实际音频集成必须配置 `CHECK_RELEASE_ID=1`；本地 `audio_system_top` 已启用。
  默认 0 只保留旧 C 单模块测试/板级 LED 演示的兼容能力，不能用于新硬件签核。
- 16 位序号允许自然回绕，要求同一声部两次 A 采样之间起音次数小于 65536；
  当前 50MHz 单事件分配器和 48kHz 输出满足这一条件。
- 声部必须在真实包络完成后回收。旧 `board_top` 的 `release_done=全1` 仍是演示占位，不能作为完整乐器顶层。
- 本地 A 的饱和混音后增加一级系统时钟寄存器，新增样本在相位/包络变化后一个系统时钟可用。
  必须给相邻 `sample_tick` 留至少两个系统时钟；50MHz/48kHz 有充足间隔。
  该寄存器连续运行，不以 `sample_tick` 为使能，不额外延后一个完整音频采样周期。
  表情和其他控制若在采样边沿附近变化，按这一级计算延迟应用，后续集成应保留此接口时序。

### 3. 八度与延音

- `octave_select=0/1/2`：以 NOTE_BASE 为基准的低/中/高档，非法档位回到基准。
- 默认 NOTE_BASE=60，13 键分别覆盖 MIDI 48..60、60..72、72..84。
- 事件在按键脉冲到达时保存音符、力度和音色，而非等队列输出时重新读取参数。
- `sustain_on` 默认由调用者接 0。打开后只改变之后松键的保持行为，重新打开不会恢复已经进入释放的尾音。
- 关闭时已经松键的声音开始正常释放；自然衰减曲线、包络时间和音质由 A 决定。
- 八度/延音 UI、物理操作键及输入同步由新的板级集成实现；本轮尚未增加屏幕或硬件操作接口。

### 4. 来源清理与队列故障

- `source_clear_valid && source_clear_ready` 接受一个清理命令。
- 匹配条件：`(voice_source_id & source_clear_mask) == (source_clear_id & source_clear_mask)`。
- 默认 PC 组可用 `id=16,mask=16` 清理；单一来源使用全 1 掩码；mask=0 明确表示所有来源。
- 清理置匹配声部 key_down/gate 为 0，尾音待真实完成后回收。持有延音不阻止故障清理。
- UART 心跳、串口断线检测与清理请求的挂起/握手仍需队友 B 接入；本轮完成的是清理逻辑和命令接口。
- `input_fault` 与 ADC 的 `param_fault` 分开；队列故障自动清理本地来源组（默认最高来源位=0）。
  本地输入停止至复位，显示应报告此状态；不得在锁存故障期间继续宣称按键正常。
- 默认 13 键可使用 5 位来源分组；改变 KEY_COUNT 或来源布局前须同步检查本地组掩码。

## 验证

- C 回归 17 项 PASS；联合侧回归 8 项 PASS（3 项系统/起音 + 4 项混音 + 1 项流水级测试）；ModelSim 编译/仿真零错误、零警告。
- 新增 4/16 声部分配测试，覆盖来源隔离、重触发、尾音、延音、清理、旧完成反馈和跨多个旧时间戳周期的抢占次序。
- 新增全部 13 键突发、事件顺序、参数快照、八度变更、背压、溢出和复位测试。
- 新增顶层溢出自动释放测试：延音开启时也释放本地按住状态，等待真实尾音完成。
- 新增 16 声部 C+A 测试：逐声部非零样本、gate 持续为高时包络重新起音，以及真实释放反馈回收。
  这不是现场 16 声部频谱证明，也不是队友新钢琴引擎的验证。
- 既有 ADS1115 和 2ms 消抖测试保持通过。
- 将 A 的串行宽位混音累加改为平衡加法树，保留原来的组合输出接口和饱和规则。
  1、3、16、32 声部均用独立 64 位参考求和核对极值和 2000 组随机样本。
- 在 A 混音输出加入一级系统时钟寄存器；新增独立参考测试覆盖该延迟、采样边沿取数、音量变化、重触发及复位。
- Gowin V1.9.12.03、GW5AT-60B、50MHz（周期 20ns）综合和布局布线完成。
  16 声部验证顶层最差 setup slack **+1.195ns**、hold slack **+0.247ns**，两类违例端点均为 **0**。
  Logic 10594/59904（18%），寄存器 2529/60780（5%），DSP 17/118（15%）。
  该顶层仍使用两个板载键和 LED，另外 11 路按键为常量并被优化；这些数字不代表正式 13 键/DAC 顶层的资源和时序签核。
- Gowin 仍有既有 A 波形表常量/算术位宽提示，以及 PR1014 时钟使用普通布线资源提示。
  波形表提示为 `16'sd65536` 截断；它和其他音色计算需在正式 A 引擎中核对。
  正式整机需按实际时钟引脚/时钟网络、DAC 和输入输出约束重新检查；此次通过不替代这一步。
