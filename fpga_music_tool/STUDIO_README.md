## 启动与试用

双击同目录的 `run_tone_studio.bat`。本机已经在项目的 `.venv-studio` 中安装 Python 3.12.14、PySide6 6.8.3 和 pyserial 3.5，无需旧脚本中的 `D:\python`。迁移到另一台 Windows 电脑后，首次启动会运行 `setup_studio.ps1`；需要 Python 3.10 或以上以及下载依赖的网络。

建议先做一个约 30 分钟的小实验（时间仅供学习参考）：

1. 保持端口为“模拟设备”，点击连接。
2. 拖动第 3 分量，观察下方单周期形状变化。
3. 改一个包络参数，保存 JSON，再载入；观察文件状态。
4. 点击“应用到设备”，等到“模拟设备已确认”。
5. 进入顶部“演奏”页，触发四音和弦或按住琴键；点击“全部松键”。“设备”页显示模拟状态。

预期：配置可保存复原，修改后草稿与设备状态分别显示。模拟设备不产生声音，模拟状态不能作为 FPGA 功能或比赛验收证据。单周期预览不模拟包络、音量或颤音的实际声音。

## 已实现

- 16 个谐波的鼠标绘制、精确输入、方向键调整（Shift 加速）。
- 纯正弦、柔和、明亮草稿，方波/锯齿的有限谐波近似与全零。
- 起音/衰减/释放毫秒数、持续电平、主音量、发声模式、颤音参数的编辑与保存。
- JSON 配置严格校验；损坏文件不会部分修改当前草稿；写完临时文件后才替换保存文件。
- 1024 点、16 位有符号单周期波表导出；零相位谐波叠加、峰值归一化、四舍六入五成双，范围 -32767～32767，每行一个十六进制字。生成依据在 `studio_model.py`。
- 真实串口枚举和后台收发，默认 115200、8N1，无硬件流控；握手、设备能力检查、CRC16 和编号回执。
- 模拟设备、虚拟琴键、四音和弦、全部松键、设备状态、通信日志。
- 草稿保存状态与设备应用状态独立；确认等待期间继续编辑，不会把旧回执误认作新草稿已应用。

混响、合唱、延迟效果器为明确标注的待开发项。

## 当前硬件边界

**能烧录只证明 JTAG 下载通道可用。** 原 `rtl/instrument_adsr_top.v` 没有UART端口；新增 `instrument_uart_top` 实现基础串口演奏，ADSR仍是编译参数，只有固定正弦。界面运行时调参、谐波／颤音／发声模式仍需后续FPGA开发，不能拿基础握手当作这些功能已完成。

NEO Dock31004 Rev1.4的UART网络已按用户原理图核对为RX=V14、TX=U15、3.3V，独立工程已加约束并生成位流；本轮没有打开实际COM、烧录或试听。优先板载DEBUG USB，实际COM和调试器工作状态仍待核对；只枚举系统端口不能证明通信。

连接实际串口却显示“固件未响应”时，核对固件是否实现协议、端口和波特率；不能凭“串口已打开”判断调参成功。当前固件没有实现协议时，这个提示是预期行为。

## 旧控制台有什么用

`main.py` 是早期综合工具：串口命令、电脑/MIDI 虚拟键盘、参数文件、波表导出、电脑音频采集及频谱。`serial_worker.py` 负责原始串口后台收发，`protocol.py` 拼接旧文本命令，`wavetable.py` 生成与导出波表，`audio_worker.py` 读取电脑音频。

旧程序的发声命令需要 FPGA 对应实现；旧启动脚本写死的 `D:\python` 在本机不存在。旧“延迟测量”用电脑 `playrec` 和相关估计，测的是电脑播放/录音路径，不能证明 FPGA 乐器的整机 ≤10 ms。频谱中的多个峰也不能自动当作独立复音。

新程序与旧控制台 JSON 格式、协议不同，载入时会明确拒绝旧格式，避免把未定义单位静默换算。旧文件均保留。
