### 实现方法与采用依据

Delay 的 `20*dry+3*delayed` 在原32位有符号范围内改用移位加法，原截断、饱和和每拍状态不变；独立64位整数参考完成2293760组边界及输入对照。HDMI保留原两级像素下降沿释放，仅末级驱动三只保留LUT，20个实际布局位置由工具报告核对；300轮/234847次精确对照和恢复故障检查通过。

USB核心与引脚寄存器分别用同一PLLA的CLKOUT0/1，两路均为48 MHz、零相位、相同VCO，未增加PLL。核心保持全局时钟，引脚分支只驱动D+、D−、OE三个寄存器。两域之间作为相关时钟正常检查Setup/Hold及复位Recovery/Removal，没有增加跨域false path。厂商PLL模型的16408次相位/周期检查、8192个引脚值、8轮复位/停钟以及真实D+/D−枚举通过；相位偏移和错误采样边沿故障被拒绝。

额外 `route_*` 时钟是同物理节点、同边沿的分析别名，仅给实现器更严格的布线目标；原来的五个原生时钟及I/O预算另有完整报告。最终59条活动命令 = 原31条 + 新相关时钟1条 + 分析别名4条 + 不确定度8条 + 别名min/max目标2条 + 显式报告13条。USB原10 ns输出预算不变；附加8 ns只作用于布线别名。LFSR短路径的0.8 ns最小延时也只作用于别名发起端；原生Hold路径继续独立检查。

报告取四类全部时钟组、原生min/max例外与原I/O预算的最低值，不只取第一组或第一个路径。额外目标不得混入原生报告，厂商固有的相关PLL输出35 ps不确定度和PLL传播延时保留。两个小电路分别在原约束下复查同一路由，除位流时间注释外配置字节及原生STA一致；报告审计的10类反例均被拒绝。完整工程的路由复用尝试未完成，不作为这个结论的证据；正式结果来自三次全量构建。

显示60位命中结果在已有S0→S1边沿采样，和坐标同步；帧提交采用state_latest乐器位，默认独立绘制器保留组合接口。触摸在既有报告接收拍预计算，保留匹配、事件及背压拍序。未增加RGB/音频延迟。颜色区域拆分虽提高Setup，却降低Hold/Recovery，未采用。

## 先核实原方案中的假设

1. P2/R2/C0是当前32声部增强明亮度版的已验证配置；不能拿旧16声部的更大Setup判断“配置漂移”。本机ClockOrder仅支持0/1。
2. 4.142ns是发起时钟插入延迟，同时存在4.133ns捕获插入延迟。首条路径为 `20+4.133−0.057−(4.142+18.858)=1.076ns`，不能单独从20ns周期扣掉4.142ns。PRIMARY八路也含控制网，不等于八个独立时钟域。ClockOrder试验没有消除PR1014。
3. 分配器的年龄是每声部5位、总160位的排列；不是32位逐拍年龄。改32位时间戳反而多864位存储，并引入计数回绕判断。
4. 模态ROM已按幅度有效13位无损打包。12288项幅度按位或为`0x1fff`；实时24位状态的低8位参与衰减。回声RAM是Q16.2，截成16位会损失反馈小数。因此“直接裁位省9块RAM”不满足音色保持要求。
5. 当前只有一个正式HDMI入口。USB主机/HID已有RTL及离线证据，独立实物验收仍欠缺；不能写成“未实现”，也不能写成“实物已通过”。

| C2 串口资源 | 两路有独立会话、超时、回复上下文，不能只保留两个接收器便直接共用解析器。改试各队列同步RAM＋队头旁路，不共享会话；功能及实际SDPB网表验证通过，但实现Hold最低51ps。 |
| C3 吉他绘制 | 将6×13次几何判断改为列预译码和每弦判断，变量位选缩至所需位宽，保留RGB/同步逐拍一致。实现少479 Logic，Setup却降到153ps。 |
| C4 存储位宽 | 检查ROM和运行状态反例，否决有损截位，未修改A核心或ROM。 |
| D1 共享包络 | 按原计划仅评估。当前R0快照、R1同时推进每组16份包络；共享计算需要逐声部调度和明确的active/release可见时刻。可能保留PCM/R958，但尚未实现或证明；18拍最终余量不等于全部内部调度空间。 |
| D2 扩展声部/提频 | 本轮不增加声部或系统时钟，维持32声部和全部I/O合同。 |

## 验证与保留结果

- 当前正式源码加新测试共246份通过ModelSim `-vlog01compat -pedanticerrors`，没有SystemVerilog模式。331份既有受保护文件和119份正式综合/约束输入哈希保持。
- 新FIFO测试以固定Git原版和独立队列模型双重核对：三种参数各60000拍，覆盖满队同拍进出、单字替换、阻塞、flush、异步复位。正式原队列也通过；破坏同拍出队的`FifoExchange`故障在201拍被拒绝。
- RAM候选另验证两种实际Gowin SDPB综合网表，各60000拍通过；删除单字旁路的候选故障被拒绝。综合厂商RAM与纯RTL模拟分开记证据。
- B1/B1R触点差分覆盖CONTACTS=1/5/6/15共240000拍，核对事件/控制/取消和复位；槽0译码故障被拒绝。
- C3几何判定638976组对照；完整屏幕差分2456173拍，包括1228895个钢琴像素、614406个吉他像素、帧原子提交及停钟复位恢复。组合候选重复通过触点/画面差分。
- C2+C3候选通过UART字节/协议/流控/回复、BLE来源隔离及HDMI 17轮恢复。增强明亮度R958顶层通过32声部四来源检查；6903组音频逐级匹配独立整数参考，13803个DAC串行字检查通过。长音频仿真用已单独证明等价的仿真ROM，不能说全部厂商原语长回归跑完。
- 原`tb_panel_octaves`旧坐标断言的既有失败没有修改或计入通过。本轮未重跑整套历史TB；实验日志中的故障注入FAIL属于预期拒绝，首次缺少音频转储目录的环境失败也保留并记录随后重跑。

## 后续空间与未完成项

下一步值得单独设计的是包络共享计算和局部时钟/短路径结构，而不是继续盲扫相同策略。共享包络应先规定逐声部使用期限、释放/抢占可见拍及快照一致性，再做独立参考；可能有资源收益，但本轮没有性能承诺。PR1014、完整DAC板外预算、USB独立实物、实体与触摸两条整机延迟仍待验收，128ps内部最薄余量不能替代这些检查。屏幕控件和远程APPLY也不因本轮优化自动完成。
