### 共同接口规则（下一版实现前确认并写入测试）

| 接口 | 两端共同负责的约定 |
|---|---|
| C → A | 音符、独立触发、保持／释放、音色、音量、变调的位宽、符号、单位和有效时刻；持续高电平不能单独表示重触发 |
| A → C | 每声部真实释放完成；尾音结束前不能当作空闲 |
| A → B | 请求到有效的周期数、16位有符号格式、缓存接收时刻和缺样本处理 |
| C → B | 控制就绪、通信故障、数据失效与恢复条件 |
| B → A/C | 统一时钟、复位及运行条件 |

- 沿用50MHz系统时钟、48kHz目标采样率、16位输出；I2C时钟只作外部信号，不另建内部逻辑时钟域。
- A在采样边界采纳参数并平滑音量／变调；变调不得修改松键匹配用的原始音符编号。
- 分配顺序为空闲、释放中、最老活动声部；被抢占琴键松开不能关闭新音符。
- 下一版 KEY0复位、KEY1切换音色、KEY2预留；切换只影响新触发声部，旧尾音保持原音色。**当前 demo 仍是 KEY1=C4、KEY2=E4。**
- ADC初始化失败、持续通信失败或数据长期失效时静音；恢复后先松开琴键，再重新演奏。
- A检查C、B检查A、C检查B；三人都逐步掌握仿真、构建、下载和本模块解释。

## 2. 依据、要求与边界

主要依据：[高云2026选题指南](./docs/sources/全国大学生嵌入式芯片与系统设计竞赛'2026FPGA赛道选题指南-高云半导体.pdf)，PDF 第15—16页（印刷页码13—14）；板卡申请见 PDF 第21页。后续正式补充通知优先于本地旧版指南，存在冲突时先核实。

视频截图只作学习参考，不能替代规则。截图中的“至少8音阶”与“至少4复音”不是同一指标：前者是可选择的音高数量，后者是同时发声数量。截图的板卡名称、录音回放建议等也不能直接当作参赛许可。

项目资料按可信度和用途分为三类：

- **官方要求（以正式指南原文为准）**：FPGA HDL 实时音频生成、实时采样运算、总延迟≤10ms、基础复音数≥4、至少2个独立可控演奏维度，以及禁止预录 PCM、整段录音或预置推流替代实时合成。

指南总体描述强调多音色切换，并在拓展项明确“≥2种乐器音色”。本项目保守地把“至少2种可辨别合成音色”作为交付目标，但不把它伪称为基础条目中的原文数量要求。具体认定有疑问时向官方确认。

### 2.2 本项目建议，不是官方硬指标

- 从单周期正弦波表开始，逐步实现4复音；第二种音色可由有限谐波组合形成，先限制音域以控制混叠。
- 初始建议采样率48kHz、最终输出16位有符号数据；以实际板卡时钟和音频器件支持情况确认。混音内部必须保留足够位宽。
- 先同一音色四复音，再做音色切换；不要求每个声部同时采用不同音色。
- 用 Python 生成单周期波表、参考结果和测试图表，不让电脑参与最终核心发声计算。
- 初期不引入 Linux、NPU、摄像头、DDR控制器、手机App、蓝牙和复杂屏幕。确有必要再论证。
- 32复音、复杂效果器、三维表情控制和≤5ms延迟属于后续挑战，不是初学阶段的完成条件。

指南允许波表合成，但不能把一段录音切成文件并触发播放，冒充逐音实时合成。保留波表生成脚本、频率控制和包络实现作为证据。

### 4.1 模块对应关系（暂定）

以下是便于开工和分支协作的模块级对应关系。模块粒度可以在接口评审后调整；四个复音声部应实例化同一个声部模块，不应复制四份不同代码。

**A：波形与合成**

- `phase_inc_calc`：音符编号转换为相位增量；
- `voice_dds`、`wave_lut`：相位累加、波表查找和音色选择；
- `adsr_envelope`：起音、衰减、保持、释放包络；
- `voice_gain`：单个声部的力度和音量缩放；
- `poly_mixer`、`saturator`：多声部混音、位宽处理和防溢出；
- Python 参考模型、定点数规则和逐样本对照测试。

**B：音频输出与系统集成**

- `sample_tick`：音频采样节拍；
- `i2s_tx`：向音频 DAC 发送串行音频数据；
- `synth_top`：连接输入、声部、混音和 I2S；
- 时钟、复位、PLL、引脚约束、下载、综合、布局布线和时序检查；
- 固定测试音输出、接线记录和整机延迟测量。

**C：交互与声部管理**

- `input_sync_debounce`：外部输入同步与按键消抖；
- `touch_or_key_if`、`pressure_if`：触摸/按键和压力数据采集；
- `event_encoder`：生成按下、松开、音符、力度和音色事件；
- `voice_allocator`：四声部分配、释放、重触发和声部抢占；
- 调试 LED 状态和输入事件测试。

接口由两人共同确认：A 与 C 确定事件字段和声部状态；A 与 B 确定采样率、音频位宽、符号格式和混音延迟；B 与 C 确定时钟域、事件传输和复位行为。

## 5. 学习方式与共同基础

每次建议安排60—90分钟：15—25分钟读一个概念，35—50分钟完成小实验，最后记录结果并用自己的话解释。时间不足可拆成两次，不要求先看完长课程。

共同学习顺序：

1. 补编程基础：变量、循环、函数、数组、二进制、十六进制和补码。
2. 补数电：组合逻辑、触发器、寄存器、计数器、状态机。
3. 学Verilog：模块/端口、位宽、组合与时序块、阻塞/非阻塞赋值，理解硬件并行。
4. 写测试平台：主动施加输入，观察波形，自动检查期望结果，不只看“编译成功”。
5. 跑上板流程：综合、布局布线、约束、下载；理解仿真通过不代表板上一定正确。
6. 补音频概念：采样率、音高、振幅、频谱、包络、混音和削波；先用Python听/看简单波形。

术语速查：RTL/HDL是描述硬件的代码；DDS是通过累加相位并查表产生波形；ADSR是起音、衰减、保持、释放的响度曲线；I2S是传送数字音频的串行接口；复音是同时发声的声部数量。

共同入门验收：每个人独立写一个计数器，完成复位与边界仿真，并在有板条件下实现按键控制LED；能解释为什么不能把Verilog当作按行执行的C程序。未通过者继续与队友结对练习。

## 7. 最小架构与接口约定

```text
触摸/压力 → 采集与滤波 → 演奏事件 → 四声部分配
                                      ↓
                         各声部DDS＋ADSR包络
                                      ↓
                             宽位混音/饱和处理
                                      ↓
                              I2S → DAC/功放 → 扬声器
```

拓展支路可从混音或事件状态旁路到 FPGA 内的 LED 指引、钢琴卷帘、频谱或波形显示。蓝牙/手机 App、曲谱下载、键位自定义和录音回传放在基础音频闭环之后；它们不能承担核心合成，也不能让上位机软件代替 FPGA 音频通路。

Python参考模型和测试工具位于开发电脑，用于验证，不在最终实时发声链路中。

在分头实现前共同确定以下合同，先用简单表格写在模块说明中：

- 事件：按下、松开、力度变化；字段含音符编号、力度和音色编号。定义有效/接收握手，避免漏事件。
- 声部：C保留音符到声部的映射，A输出各声部是否仍活跃；释放阶段结束前不能误判为空闲。满声部的抢占策略先统一并测试。
- 音频：采样率、输出位宽、补码格式、左右声道映射、内部累加位宽、舍入及饱和策略。
- 时序：谁产生样本节拍、数据何时有效、I2S何时锁存；共享时钟域时仍要写清各模块延迟。
- 复位：极性、上电流程、默认静音状态；外部异步输入须同步，多位跨时钟数据不能只逐位加两级寄存器。
- 参数：音高、音量和音色在什么时刻生效；切换是否需要平滑处理。

尽量采用简单一致的系统时钟与时钟使能，但音频时钟来源必须与板卡及DAC匹配；不能用不精确的分频假装达到了目标采样率。必须跨时钟时，采用有验证依据的握手或FIFO方案。

## 8. 测试与验收

### 8.1 每个模块都应有的证据

- 输入、输出、时钟、复位、位宽和有效时刻说明。
- 至少一个正常用例、一个边界用例、一个复位/异常用例。
- 可重复运行的测试命令或GUI步骤、工具版本、实际输出及期望输出。
- 数学模块使用Python参考模型，显式对齐定点缩放、舍入、截断、饱和和流水线延迟。
- 如果只完成仿真，明确写“尚未上板”；没有安装工具则写“未运行”，不得宣称通过。

### 8.2 系统测试清单

- [ ] R1：两维输入分别变化时效果正确，记录抖动、误触发与丢失情况。
- [ ] R2/R7：检查FPGA实时发声路径、波表来源，脱离开发电脑运行。
- [ ] R3：覆盖触摸扫描、压力滤波、事件处理、合成和音频输出的延迟；多次测量保留原始数据和最大观测值，明确仪器分辨率及局限，不能只报均值。
- [ ] R4：四路不同频率可同时发声，结合参考频率、频谱和源码证明独立性；不能把一个音的谐波当成多个独立声部。
- [ ] R5：包络各阶段、动态音高、最小/最大力度、混音饱和、连续按下松开、声部满载。
- [ ] R6：检查I2S位对齐、声道、符号与输出样本一致性，不仅凭耳听判断。
- [ ] 项目音色目标：两种可辨别音色，切换和音量变化无明显异常跳变，保留测试条件。
- [ ] 维度口径：单独演示至少2个演奏维度，以及至少2个表情/合成参数维度；记录输入、参数和音频结果的对应关系。
- [ ] 资源与时序：保存综合和布局布线报告，核查时钟和约束覆盖；无约束的路径不算时序通过。
- [ ] 稳定性：建议至少30分钟连续/重复演奏测试（项目内部门槛，不是官方规定），记录卡音、异常复位和音频中断。
- [ ] 可复现性：由非主开发者按说明重新生成、下载和演示，记录代码版本与板卡版本。

延迟终点先区分数字I2S输出、模拟输出或声学输出，报告测量口径；包络本身也影响“出现可检测声音”的时间。采用实际演奏配置测量，不得为测试绕过滤波或包络，却把结果写成整机延迟。最终口径以官方细则为准。

音频功放可能为差分/桥接输出，测量前查手册并由熟悉仪器的人确认接法，不能把任一扬声器端随意接示波器地。先低音量、低增益测试，不直接满幅接耳机。

## 9. 拓展与风险降级

基础全部通过且提交缓冲充足时，只先选择一条拓展路线：

1. 声部扩展：4 → 8 → 16 → 32，逐级评估资源、时序、有效发声和混音质量。8/16是内部台阶，不冒充达到指南的≥32复音拓展项。
2. 表情与音效：在两维基础上研究第三维、滑音/颤音或简单数字延迟效果。不要一次实现混响、合唱和复杂物理建模。
3. 低延迟与展示：优化实际链路并给出前后对比，增加简单LED反馈。
4. FPGA可视化：先做LED节拍/音符指引，再择一实现实时波形或频谱显示；若使用屏幕，单独验证视频时钟、缓存和资源占用，不能依赖上位机代画。
5. 无线与演示完整性：在基础作品稳定后研究蓝牙/串口与手机App的曲谱下载、键位自定义或录音回传；所有外部链路失效时，核心乐器仍应能独立演奏。

指南核心吞吐指标关注“同时活跃可闻独立振荡器数量 × 实际音频输出采样率”，过采样不叠加加分。共享计算资源不等于禁止，但各逻辑声部仍须有独立状态并满足采样截止时间，具体计分口径需官方确认。

| 风险                       | 处理方式                                                                |
| -------------------------- | ----------------------------------------------------------------------- |
| 编程/数电基础跟不上        | 减少同时学习的模块，结对练习；先解释与验证小电路，不复制整机代码        |
| 板卡或许可迟迟不到位       | 仿真和参考模型继续；上板相关任务保持未验证，明确最后决策日期            |
| 无声音                     | 先验证电源、电平、时钟与固定I2S样本，再检查合成和交互                   |
| 音量溢出、爆音或高音混叠   | 回退到单音/小音域，检查位宽、参数连续性和频谱，不用加大音量掩盖         |
| 两维传感器不稳定           | 选更容易验证的传感器/机械方案；按钮只作阶段调试，不擅自删除两维基础要求 |
| 基础指标未完成、截止日临近 | 冻结所有拓展；评估剩余必做项能否完成，不把不完整作品写成达标            |
| 规则与视频/旧指南不一致    | 记录原文和版本，向官方确认；不按“更容易”的解释自行放宽                |

时间管理：先核定正式提交日，内部功能冻结建议放在提交前7天，材料与复现检查放在提交前3天。若排期装不下这些缓冲，重新评估范围与参赛可行性，不能移动官方日期。
