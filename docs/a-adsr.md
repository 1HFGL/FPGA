## 用途与边界

ADSR 控制一个音符的音量随时间变化：Attack 渐强，Decay 衰减到保持电平，Sustain 在按住时保持，Release 在松开后渐弱到零。S 是电平，不是固定的持续时间。

这一版在现有正弦 DDS 后加线性包络，不改变波表、音高计算或 B 的 DAC 输出协议。它让声音有起落，但不等于已经实现钢琴或其他真实乐器。波形/谐波、力度、四声部独立包络与混音属于后续工作。

概念参考为用户提供的[包络文章及截图](https://zhuanlan.zhihu.com/p/81771109)。网页访问返回 403，依据的是会话中可见截图。RTL、测试与整数参考模型为本项目独立实现，没有复制文章代码。

## 公共接口

所有控制信号与 `clk` 同步。`rst` 是高有效同步复位，优先级最高。不要直接接未经同步、消抖的物理按键。

| 信号 | 规则 |
| --- | --- |
| `sample_tick` | 音频样本请求/时钟使能；不是另一个时钟；支持连续多个时钟请求 |
| `phase_inc[31:0]` | 与原 DDS 相同；在请求边沿读取 |
| `gate` | 电平：1 表示按住，0 表示松开；仅在采样请求边沿生效，短于采样间隔的完整按下松开可能被漏掉，应由 C 保持事件状态 |
| `retrigger` | 可选的一个 `clk` 周期重触发脉冲；未使用时接 `1'b0`；两次采样之间会暂存，多个脉冲合并一次，不是事件 FIFO |
| `sample[15:0]` | 有符号补码；无效周期保持上一次输出 |
| `sample_valid` | 输出样本有效；比原 DDS 多一个 `clk` 周期，不可直接用原 `sample_tick` 代替 |
| `env_level[16:0]` | 当前包络，unsigned Q1.16；0 静音，65536 精确单位增益；用于观察，连续请求时它比音频输出领先一拍 |
| `voice_active` | 包络尚未回到空闲或当前仍输出最后一个非零样本时为 1；供后续声部分配参考 |

包络状态：0=IDLE，1=ATTACK，2=DECAY，3=SUSTAIN，4=RELEASE。状态表示当前电平更新之后所处阶段，例如刚达到峰值时已切换到 DECAY。

### 按下、松开与重触发

- 第一次 `gate=1` 的采样边沿执行第一步渐强。
- `gate=0` 优先于重触发，从当前电平执行释放；在 Attack 或 Decay 中松开也一样。只在进入释放时记录起点，非零起点均在 `RELEASE_SAMPLES` 次采样更新后归零；起点已经为零时直接空闲。
- 在 Release 中重新按下，或按住时给 `retrigger`，从当前电平重新渐强，不突然清零，并重新使用完整 `ATTACK_SAMPLES` 点时长。DDS 相位不随按键重置，只有 `rst` 清相位。
- `retrigger` 必须是脉冲，持续为 1 会每个采样重新触发。待处理脉冲遇到采样边沿的 `gate=0` 时丢弃；复位也清除待处理脉冲。
- **松开后必须继续送 `sample_tick`，包括完全静音时也正常返回零样本。** 不要用 `gate` 屏蔽采样请求，否则 Release 停住或 B 无样本可取。
- 保持电平为 0 但仍按住时，声音为零，声部仍活跃，直到松开回到 IDLE。

### 有效时刻与 B 接口

假定第 E 个时钟上升沿 `sample_tick=1`：

1. E 边沿之后：原 DDS 的旧相位样本与本次更新的包络同时就绪。
2. E+1 边沿之后：对应乘积出现在 `sample`，`sample_valid=1`。
3. 同步下游在 E+2 边沿读取这个有效样本。连续请求可每个时钟输出一个样本。

无效周期清 `sample_valid`，但样本寄存器保持。复位清所有流水线有效位、样本、包络和待处理触发。

连接 B 时，保持同一时钟域和一致复位：B 的 `sample_request` 接新模块 `sample_tick`，新 `sample/sample_valid` 接 B 的数据/有效输入。必须用队友最新顶层确认输出接收时刻和复位释放方式。当前仓库的 B 在帧边界提出请求，新样本用于后续帧；本次只跑了原 B 回归，未改写或验证队友的板级顶层。

## v2 参数与时间

参数在实例化/综合时确定，不是运行时配置端口。根据用户提供的队友 README，采用下面这组初始音色参数；50 MHz 为该团队文档中的系统时钟计划，48 kHz 为采样目标，本次仿真不能代替板上时钟/采样率测量。

| 参数 | 默认值 | 48 kHz 时的行为 |
| --- | ---: | --- |
| `ATTACK_SAMPLES` | 96 | 起音 2 ms，从当前幅度到 65536 |
| `DECAY_SAMPLES` | 24000 | 衰减 500 ms，从峰值到保持幅度 |
| `SUSTAIN_LEVEL` | 6554 | 约 10% 峰值幅度；不是主观响度的 10% |
| `RELEASE_SAMPLES` | 5760 | 从任意非零当前幅度释放 120 ms |

按 `采样点数 = round(实际采样率 × 时间秒数)` 选择参数。以上时长按 N/Fs 标称换算；第一步在识别按下/松开的采样边沿执行，下一段从本段第 N 步之后的下一次采样开始。事件识别自身还有 0～一个采样间隔的等待。

例如想改为 5 ms 起音，在 48 kHz 下实例化时设 `.ATTACK_SAMPLES(32'd240)`。更换 `clk` 频率而保持实际采样率不变，不需要改这些值；更换采样率需要重新计算。仿真中缩短采样间隔仅用于加速，不改变检查的采样点数。

**迁移注意：信号端口保持不变，三个 STEP 参数已删除。** 队友若曾显式指定 `ATTACK_STEP`、`DECAY_STEP`、`RELEASE_STEP`，需要改成对应的 `*_SAMPLES` 参数；步长值不能直接当成采样数。只使用默认参数的实例无需改端口连接。`SUSTAIN_LEVEL` 仍是 17 位无符号幅度，时长参数改为 32 位无符号采样数。

边界规则：时长参数 0 按 1 个采样点处理，在下次采样到达终点，避免除零与卡住。A、D 均为 0 时，仍先输出一个峰值样本，再到保持幅度。保持幅度超过 65536 时钳到 65536；保持为零且 gate 仍为 1 时保持 SUSTAIN/active。起音或衰减的距离为零时，仍计满该段的采样数。

### 为什么释放时间能固定

旧版每拍减固定步长，松键时幅度越大，释放越久。v2 在每段开始时将总距离分成 N 步：

```text
基本步长 q = distance / N
余数     r = distance % N
每步走 q；将 r 加入余数累加器，累计到 N 时再多走 1。
```

第 k 步累计变化为 `floor(distance*k/N)`，第 N 步强制取准确终点。下降曲线为 `起点 - floor(distance*k/N)`；因此从幅度 1 释放也能保持到最后一步，不会因步长变成 0 而卡住。除数是三个综合期参数，不是运行时变化的输入；本次资源和关键路径已由高云报告确认，详见 [验证与交接记录](a-adsr-validation.md)；队友整机仍需重跑。

10 月 3 日将第一步单独处理：初始误差为 0，r<N，所以直接走 q；后续才累计误差并判断额外一步。Decay 起点固定为 65536，初始化可预计算。默认计数器从 32 位缩至 15 位，误差加法扩一位保留进位；大参数仍自动使用足够位宽。这些修改缩短组合路径，数学曲线和逐拍更新规则保持一致。

### 队友读代码的顺序

1. 先看 `voice_adsr.v`：DDS、包络、乘法器如何连接，以及 E/E+1/E+2 的有效时序。
2. 再看 `adsr_env.v`：参数单位 → 端口 → 阶段选择 → 步长与余数 → 寄存器更新。`ticks_left` 为剩余采样数，`base_step` 为整数基本步长，`remainder/error_acc` 保存并累计小数部分。
3. 最后看 `sample_gain.v`：无符号包络如何转换为正有符号乘数，为什么保留 34 位乘积，以及如何缩放到 16 位音频。

以上三份 RTL 已补中文注释，解释设计原因、位宽和时序；测试平台中的闭式直线参考与 RTL 的逐步余数实现相互独立。

计算为 `floor(signed_sample * env_level / 65536)`。16 位有符号样本乘零扩展后的 18 位有符号正增益，保留 34 位乘积，再算术右移 16 位。向负无穷舍入，误差小于一个输出最低位。由于增益限于 0～1，结果必在 -32768～32767 之内；单位增益时正负幅值均精确保持。后续多声部混音仍需单独扩位和限幅。
