## 已适配与下一步

主工程沿用8位来源：实体0..12，电脑128..255。触点模块预留64..68（0x40～0x44），其余16..127未占用；正式触摸尚未汇合。实体队列故障只清0..15，PC失联只清最高位为1的来源；触摸取消只匹配掩码0xf0/值0x40。起音代次只在实际采样后确认，回收同时检查代次和真实尾音完成；排序沿用主工程无回绕年龄排列，并按C规则优先抢最老已松开声部。

每键四项暂存、64项FIFO、八度按下快照、延音/按住状态分离及故障隔离已接入；板级KEY1已接入三档音区、复位中档，延音关闭。旋钮0音量、旋钮1全局弯音接到真实音频计算。新增主Verilog联合测试见 `run_performance_tests.ps1`，本轮所有既有tb和C独立脚本与基线保持字节一致。

KEY2模式在分配器接受音符事件时写入4位`timbre`的最低位：0钢琴、1吉他，其余位0；适配层转换为A核心的相反编号，不改变C合同。R0锁存音符、参数及整批代次，R923原始结果有效，正式音区版旁路明亮度，R924缓存；确认只对应这批结果，忙时屏蔽旧release_done，避免旧代次回收新声部。

已有声部保留原音色快照，两音色共享同一16席位，模式切换不清队列、不产生E4，不取消本地或电脑尾音。显示分别读取钢琴/吉他仍持有的已分配音符，整帧切换主体及高亮；音符不等待帧刷新。触点转换已有独立模块，正式USB来源汇合仍未实现。正式新核心联合测试见run_final_tests.py，原R7测试仅作为显式兼容配置回归。

下一步确定触摸控制器和延音入口；实体八度入口已确定为KEY1，仍需实物验收，核对实物旋钮行程、按键抖动、接线及整机模拟延迟。用户持有板卡；本轮没有操作下载器，也没有实物验收。

## 已解码触点接口（2026-10-17）

`touch_contact_tracker.v`目前按5点配置，全部信号在50MHz域。`frame_valid&&frame_ready`接受一次**全部活动触点的完整快照**：`contact_active[4:0]`、五个8位ID、五组12位像素x/y。HID层必须先组装分包、过滤无效报告并完成坐标转换；不能把增量包/单个触点报告直接当完整快照，缺失ID会被解释为抬手。模块在接受时锁存音区/音色。

输出音符`event_valid/ready`、`event_on`、`event_source`、`event_note`、固定力度96及`event_guitar`；全部等待接受时保持。单份快照最多10条音符事件，先释放旧音再触发新音。来源按内部槽分配，不随数组重排变化；同坐标不同ID可分别发声。换区不改当前持音；滑到另一键才按新音区触发。模式变化后已有触点冻结至抬手。

`control_valid/ready`输出kind=1模式明确选值、2音区明确选值、3延音翻转；控件只在接触开始时发一次，控件接触不会滑进键区发音。`cancel_valid/ready`输出0xf0/0x40来源取消；断连、坏流或重复ID先等已提出事件接受，再执行取消，`fault`锁存到复位。共同复位可撤销尚未接受的事务；正常背压下有效位/数据稳定。上层USB接收队列必须按实际报告率提供有界积压/故障清理，不可静默覆盖按下/松开。

此模块已接真实16声部分配器做独立联合测试，覆盖28条精确事件、五指、满16席、背压/断连及共同复位，且“丢松键”故障注入被拒绝；单独综合无锁存、无BSRAM和DSP。它尚未实例化进正式顶层；USB/HID、报告跨域、全局延音/控件状态与三路仲裁是剩余集成工作。
