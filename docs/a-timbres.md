# 四声部柔和／明亮音色：接口与验证

2026-10-06，为独立四声部核心增加两种单周期波表。柔和音色使用原正弦表，明亮音色加入二、三、四次谐波；每个声部在新触发时独立锁存音色。保持或释放期间切换外部音色选项，不会立即改变正在发声的波表。ADSR 默认参数、四路相位独立性、混音及 R3 输出时刻保持原约定。

本说明面向 A/B/C 交接。已有团队 demo 顶层、C 的实体按键音色选择及 B 的输出连接仍需要集成；这里的 WAV 来自真实 RTL 仿真采样，不是 FPGA 板卡或 DAC 的录音。

## 两张波表怎样生成

两张表均为 1024 点、有符号 16 位、单周期数据。地址 `k=0..1023` 对应 `theta=2*pi*k/1024`：

```text
soft[k]   = round_away(32767 * sin(theta))
bright[k] = round_away(32767 * (8*sin(theta) + 4*sin(2*theta)
                                  + 2*sin(3*theta) + sin(4*theta)) / 15)
```

`round_away` 表示四舍五入，恰好半整数时远离零，与原 `gen_sine.ps1` 一致。文件中的四位十六进制数保存二进制补码；例如 `FFFF` 表示 -1。明亮波形各项绝对权重之和为 15，除以 15 限制幅度，避免直接叠加谐波溢出。实际 ROM 峰值为柔和 ±32767、明亮 ±24384，两张表的整数采样和均为 0。

这不是按两种音色分别调整到相同响度或相同峰值。明亮音色的基波幅度较小，其可区分性用谐波组成说明；不能只以“更响／更轻”作为音色区别的证据。波表只保存一个周期，音高、包络、声部混合仍由 FPGA 在运行时实时计算。

| ROM 数学检查 | 基波 | 二次谐波／基波 | 三次谐波／基波 | 四次谐波／基波 |
|---|---:|---:|---:|---:|
| 柔和 | 32766.958035 | 约 0 | 约 0.000001 | 约 0 |
| 明亮 | 17475.755582 | 0.499999 | 0.249998 | 0.125001 |

以上为 1024 点 ROM 的离散傅里叶分析。极小的非目标分量来自整数取样量化，不是新增独立声部。

`wave_lut_timbre` 和 `voice_timbre_adsr` 的 `timbre` 为 1 位：0 柔和、1 明亮。两者保留 `ROM_FILE` 作为柔和表路径，新增 `BRIGHT_ROM_FILE` 为明亮表路径，默认分别为 `rtl/rom/sine_1024.mem`、`rtl/rom/bright_1024.mem`。

`voice_bank_adsr` 新增 `voice_timbre[3:0]`，每个声部占 1 位，声部 0 对应 bit 0。全部输入应属于同一个 `clk` 时钟域；`sample_request` 仍是采样使能。其他公开端口、`rst_n` 低有效同步复位、默认包络 A96/D24000/S6554/R5760、增益字段和 `MIX_SHIFT=5` 沿用[四声部接口](a-poly-adsr.md)。

旧的单音 `voice_dds`、`voice_adsr` 仍是原正弦接口。已有 `voice_bank_adsr` 实例若暂时不用音色控制，需要显式连接 `.voice_timbre(4'b0000)`，不能把新输入悬空；单声部新模块对应接 `.timbre(1'b0)`。

高云综合四声部核心需要 `phase_acc.v`、`wave_lut.v`、`wave_lut_timbre.v`、`adsr_env.v`、`sample_gain.v`、`voice_timbre_adsr.v`、`note_phase_lut.v`、`sample_mixer4.v` 和 `voice_bank_adsr.v`，以及两份 ROM 文件可被搜索到。仿真测试平台不加入综合源文件。ROM 使用相对路径时，工程的搜索路径须包含仓库根目录；不要只修复柔和表而漏掉明亮表。

## C 的音色字段如何连接

现有 C 的 `voice_timbre_flat` 在四声部配置下共 16 位，**每个槽位占 4 位**。A 的 `voice_timbre` 共 4 位，每个槽位占 1 位。集成时应逐槽解码，只有代码 1 选择明亮，代码 0 或其他未支持代码选择柔和：

```verilog
wire [3:0] a_voice_timbre;
genvar i;
generate for (i=0; i<4; i=i+1) begin: g_timbre_decode
    assign a_voice_timbre[i] = (c_voice_timbre_flat[i*4 +: 4] == 4'd1);
end endgenerate
// voice_bank_adsr 实例：.voice_timbre(a_voice_timbre)
```

上例的 `c_voice_timbre_flat` 代表 C 输出连线，实际命名由集成顶层决定。不能直接取整个总线的低 4 位，也不能简单对每个四位字段做非零判断，否则会把不同槽位或未支持代码误解释为明亮。

C 还需要在音色切换后为新音符送出正确的音色字段，并在同槽位重新触发或抢占时给出独立 `voice_retrigger` 脉冲。当前 C 普通事件路径仍有固定音色 0 的连接；仅升级 A 不会自动让实体按键开始切换音色。

## 音色何时锁存

1. 新音符被采样请求接受时，音色和首次起音样本同拍生效。起音为 0／1 点的参数配置也使用同一约定，不等待状态停留在 Attack。
2. 同拍 `retrigger=1` 优先使用这一拍的 `timbre`。该脉冲必须是一个 `clk`，不能持续拉高。
3. 两次采样请求之间出现重触发时，同时暂存它的音色。之后即使外部选择改变，下一个请求仍使用被暂存的音色；多个脉冲合并为一次，最新事件的音色获胜。这不是事件 FIFO。
4. 没有重触发时，保持或释放中的音符继续使用原音色。`gate=0` 的请求优先推进释放，并丢弃待处理触发。重新触发使用新色，但相位连续，不强制从零开始。

音符与增益仍按原接口在请求时采纳；本轮仅给触发对应的音色增加快照，不把全部控制字段改成事件队列。C/B 必须保持各槽位音符、触发、音色与保持状态的语义一致。

## 高音安全回退

明亮表最高含四次谐波。为了让这些设计谐波低于 Nyquist 频率，要求 `4*f < Fs/2`，对应相位步长：

```text
phase_inc < 0x20000000  → 按锁存音色选择波表
phase_inc >= 0x20000000 → 当前采样使用柔和正弦表
```

按平均 48 kHz 采样计算，阈值为基频 6 kHz，等于阈值时也回退。回退不清除原来锁存的明亮选择；如果后续音高回到阈值以下，该声部会恢复明亮波表。相位继续累计，ADSR 和音高不因回退而重启。

本版计划的 MIDI 60～72（C4～C5，约 262～523 Hz）全部低于阈值，两种音色均可使用。这个保护只针对加入的二、三、四次谐波；有限地址位宽及整数幅度仍存在量化杂散，不能据此宣称全音域完全无混叠，也没有完成跨越回退阈值时的听感平滑处理。

## 流水线与释放反馈

| 上升沿 | 更新内容 |
|---|---|
| R0 | 接受请求；决定本次音色、读旧相位、推进包络、快照增益 |
| R1 | 各路波形与 ADSR 相乘后的样本就绪 |
| R2 | 各路增益缩放样本就绪 |
| R3 | 混音样本、`sample_valid`、饱和标志更新 |
| R4 | 同步下游读取 R3 输出 |

两张同步 ROM 并行读取，选择位同步保存，没有增加流水线级。仍支持连续请求；请求到有效是 3 个时钟间隔，在 50 MHz 下为内部 60 ns。该数字不包含按键处理、B 的缓存、串行传输与 DAC，不能代替整机延迟。

释放反馈继续等待每路流水线中的最后零样本到达混音输出；声部之间可能相消，因此不能只根据混合总和是否为零来回收声部。松键后必须继续提供采样请求，才能推进释放与尾音反馈。
