# 当前音频、输入与合成合同

正式入口为piano_performance_top和piano_hdmi_top，均启用USE_MODAL=1，13实体键和UART共用16声部，KEY1切换中→高→低→中音区。KEY2只切换钢琴/经典摇滚电吉他，KEY0复位回钢琴和中音区；已有声音保留起音时的预设。音频50MHz系统时钟、48kHz采样、16位补码输出。

## 数据流和职责

```text
13键/板键 → 同步/消抖 → 按键事件 ─┐
UART → 收字节/组行/协议 → PC事件 ─┼→仲裁→C声部分配/触发代次
                                  ↓
ADS1115 → 音量/弯音 → 平滑 → 代次适配 → A模态声部池
                                               ↓
                            synth_top → 串行发送 → PT8211-S
                                               └→显示副本
```

A提供模态合成、ROM生成与定点参考；C负责输入、来源/事件/分配；B负责适配、采样截止时间、音频输出、显示、顶层和约束。C独立工程保留在upstream/fpga_interaction，不整目录加入主GPRJ。

主工程只采用voice_bank_music_pipe一套16声部核心，来源为队友master e18160e。voice_bank_modal_adapter只转换0钢琴/1吉他到A的1钢琴/0吉他、并衔接C代次，不改变音色公式。基础波表/包络库仍被兼容回归依赖；综合日志确认未采用的voice_bank_adsr/末级增益路径被裁剪，不并行占用第二套硬件声部池。

## 采样有效时刻和代次

一次请求在sample_request且!busy的上升沿接受，记为R0；A锁存音符、gate、起音事件、预设、全局增益和频率比。每声部56拍，共享处理27拍，16声部R923给原始sample_valid；正式版关闭明亮度，B在R924直接缓存原始样本；计算至缓存18.48µs。

正式REQUEST_LEAD_HALF_EDGES=60，下一真实音频帧前至少976个50MHz系统拍请求，严格大于924，准备余量至少52拍/1.04µs。音频帧间距1041/1042拍，不改变48kHz采样率。忙时额外请求报告overrun；正式运行不能出现overrun或持续欠载。

C起音代次16位，适配层在R0保存整批代次，以与已返回结果的代次差生成单次重触发。结果返回后R924才确认；忙时和valid尚未消费时屏蔽旧release_done。C只有gate已松开、真实尾音结束且代次相等才正常回收。计算中抢占/重按产生的新代次不能被旧批结果确认；下个请求再消费。

模式在分配器valid&&ready时随音符锁存，与KEY2有效切换同拍的新音采用新模式。两个来源同音独立占位；旧来源松键不能关掉被抢占后的新归属。满载优先抢最老松键尾音，再抢最老按住音。

音频缓存保持边界同拍输入留到下一帧，左右声道发同一样本。功放sounding包括箱体状态与最后输出，变低后再按三个真实输出帧排空；不能按松键或占用计数立刻关功放。启动首帧允许零样本，复位恢复低增益4096/65536及原音高。

R4/R6/R7仅属于明确选择的基础兼容配置。原队友测试不修改，使用单独生成的测试包装参数验证兼容合同；这些通过不作为当前R924三音区入口的证据。

## 音色与位宽

钢琴为48槽模态合成，分量各有32位相位、幅度与衰减，包含分音轻微失谐、起音噪声及C3/C4/C5/C6参考的频谱包络插值。吉他为31分量、拨弦噪声/短暂起音滑落，经过4倍插值的失真曲线与两级箱体低通。钢琴绕过吉他效果链；预设切换不把旧音送入另一链。

钢琴起音64点/释放4096点，吉他起音16点/释放2048点；释放约85.33/42.67ms，吉他另有箱体收尾。按住时分量自然衰减，无旧固定1.2秒清零。重触发有64采样点连续性修正。实体键固定力度100，PC沿用原协议的力度字段。

幅度Q16.8、衰减Q0.24、包络17位Q1.16。16个有符号样本先扩位累加；钢琴总线右移3位，吉他总线右移2位再进失真，效果后缩放并与钢琴合并。最终22位混音乘无符号Q1.16总增益，40位乘积显式右移/饱和到16位；不在B额外乘一次总音量。原始非线性公式/箱体系数保持A版本，不能据当前仿真宣称抗混叠已全面完成。

ROM含义：
- piano_v3_modes.mem：两预设/各音高的模态参数，不是录音波形。
- sine_1024.mem：单周期正弦。
- rock_v2_shaper.mem：非线性传递曲线。

生成依据在model/gen_piano_v3_rom.py、gen_rock_v2_rom.py、piano_reference_fit.json、piano_reference_sources.json；原录音只用于离线分析。check_music_pipe.py独立定点模型对照4/16声部输出、状态、旧黄金摘要和最终静音。音色真实感仍需实物试听，不能由数值一致代替听感验收。

## 双旋钮与I2C

ads1115_knob_if采AIN0音量/AIN1弯音，PGA±4.096V、860SPS、每通道等待1.5ms。50MHz下请求350kHz，四分之一周期向上取整36拍，实际约347.22kHz，低电平1.44µs。当前SCL推挽，不支持时钟拉伸；模块供电/上拉为3.3V。

按0～26400对应0～3.3V映射0～127，负码钳0，过量程钳127；整对发布，2对有效后ready。FILTER_SHIFT=0/SLEW_STEP=127关闭ADC端重复慢滤波，只保留48kHz音频域斜坡。复位先等CONV_WAIT+0.1ms；NACK丢弃整对，保留最后有效参数，重试不计入正常响应预算。

音量为round(65536×value/127)，弯音码63/64中心死区，端点频率比58386/73562。piano_controls保持17位Q1.16增益与18位频率比，每请求分别最多变化1024/256；新核心频率比只需要有效低17位。请求沿锁存上一稳定值，全批声部使用同一对参数；全部旧音、尾音及新音保留相位连续。负定点右移采用向负无穷取整。

每通道81个I2C数据/ACK位＋3次START/3次STOP，含转换等待约1.76ms；两通道非同时采样。之前定时ADC模型最大观测8.222ms是输入阶跃到音频参数稳定，加入新核心后仍须按当前批延迟复核，不能直接冒充整机旋钮→模拟输出测量。模拟RC、真实噪声/中心校准、DAC与音箱等待另计。

## UART、反馈和未实现边界

保留115200/8N1、NOTES/STATUS、MAX_VOICES=16与TONE=PIANO_GUITAR。HELLO重连、PANIC、看门狗只清理PC来源，不改变所选模式或其他来源。KEY2负责模式选择；本轮不移植A试听入口的PRESET/CONTROL命令。

实体事件源0～12，PC源0x80|note；本地故障清理掩码0xF0/值0，PC清理掩码0x80/值0x80。每键暂存/FIFO、背压及来源规则保持C接口；板级KEY1提供三档八度，延音关闭。KEY1经同一2ms消抖，每次有效按下循环1→2→0→1；和琴键同拍确认时，新起音采用新音区。event_encoder按下时锁存音符，松键仍释放旧音符；UART绝对音符不叠加板级音区。

显示从已分配且仍持有的voice_key_down和音色标记生成两套13位高亮，窗口基音随低/中/高取MIDI48/60/72，音区与掩码同拍寄存；越区旧音继续发声但不画成当前音符。只读最终样本，不反压音频。USB触摸、混响、32声部留待后续，完整比赛目标见PLAN。PT8211-S为LSBJ右对齐接口，赛题接口口径、模拟总延迟及外部时序仍需闭合。


## 历史记录：第三表情维度（已由当前 KEY1 音区方案取代）

> 以下仅适用于旧 expression3 位流。当前正式入口停用明亮度，KEY1 切三音区，缓存恢复 R924；不再执行短按调暗／长按恢复。

本次在队友最新master `aef94e5`上接入明亮度，保留31005底板J13接线、模态钢琴／经典摇滚、16复音和HDMI画面。两个正式入口均启用：旋钮0音量、旋钮1弯音、KEY1明亮度；KEY2继续切换乐器。KEY1短按每次调暗16级，到0后再次短按回127；长按约0.5秒恢复127，复位也恢复127。KEY1不再兼作C4，外接13琴键映射不变。两键同时按下仍会触发KEY2切音色，不再作为第三维恢复手势。

明亮度由FPGA混音后定点低通实现，默认127逐样本保持原PCM；三拍音频流水线使正式缓存合同由R924变为R927，原60个半边沿请求提前量保留，尾音归零后再关闭功放。屏幕观察过滤后的音频，显示不反馈控制。明亮度改变谐波比例和部分能量，不能称为真实力度传感或模拟底噪修复。

新验证入口`verification/scripts/run_expression_tests.ps1`；整合结果与新位流身份见`verification/evidence/expression/summary.json`。旧e18160e基线的31004／旧接线试听包不适用于当前J13接线；请从本次整合后的正式工程构建或使用新包。既有PR1014、DAC完整外部时序、模拟总延迟及新增听感仍需实物验收。PPT第12页的≥3维是扩展目标，基础要求仍为≥2维。

## 当前KEY1与明亮度参数

正式顶层默认 `ENABLE_OCTAVE_KEY=1`、`ENABLE_BRIGHTNESS=0`；公共核心的音区键参数默认0以保留独立旧测试合同。若两参数同时置1，音区键优先且旁路明亮度，避免同一按键同时调音高与音色。只有显式关闭音区键后，旧明亮度配置才可启用。两旋钮和A模态参数不变，不加入新的增益或失真。
