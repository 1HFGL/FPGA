## 3. 低延迟实现候选及选择标准

### 3.1 先固定测量合同

把路径拆为：稳定按键输入→同步消抖→事件握手→声部状态→采样请求→样本有效→串行字完成。每一段分别计时，报告系统时钟周期数和微秒。

数字仿真的起点是测试平台施加并持续保持的新按键电平，不冒充机械接点第一次接触。有抖动的用例另外记录最后稳定时刻及抖动持续时间；不通过减少消抖来掩盖误触发风险。

终点至少记录：与新事件对应的首个有效PCM样本、串行线上该样本右/左声道各自最后一位完成。已有背景声音时，与未添加新事件的参考轨迹比较，不以输出本来非零代替新音响应。数字非零判据固定为整数样本绝对值至少1，并明确它不是耳机可闻阈值。

真实模拟输出、功放开启时间和测量噪声不由RTL仿真代替，仍留给硬件测量。不得把内部延迟结果标作整机≤5ms或≤10ms验收。

### 3.2 优先比较“临近帧边界请求”

不改变A的R0到R3合同，不改变48kHz平均帧率，不直接删掉保证左右一致的活动样本寄存器。

候选是在每帧最后一个BCK位周期开始时请求下一帧的样本，而不是在本帧开头请求。名义50MHz／48kHz／16位立体声下，距离下一帧边界约32或33个系统周期，足以容纳当前R4接收。这使计算靠近实际发送时刻，减少旧方案近一帧的缓存等待，收益量级是几十微秒，不是几毫秒。

- `sample_tick`仍分别给出位时钟使能和发送帧边界；新增或显式区分样本准备事件，不混用两个事件。
- `synth_top`增加有明确合法范围的请求提前配置，默认兼容原通用合同；主钢琴配置仅在测试通过后启用新策略。
- 启动仍允许静音首帧；复位丢弃旧缓存；同拍输入及边界采样规则保持明确。
- 提前窗口必须覆盖上游最大计算延迟及接收拍。参数组合不足时应在验证入口明确拒绝，不能静默产生欠载。
- UART取消事件也使用采样请求，必须重跑取消、来源隔离、抢占及释放边界测试，不能只测新音首帧。
- 修改前后用同一固定音色、事件序列、采样率和位宽比较。保留旧配置可复现的结果。

这一候选只有在最坏数字延迟下降、正常运行无新增欠载、样本/左右声道一致且达到以下工程门槛时才进入主配置：相同50MHz约束下全部已约束路径无新违例，最差setup裕量至少2ns、hold非负；相对同轮主钢琴基线，逻辑单元增加不超过128、寄存器增加不超过64，DSP/BSRAM/PLL不增加。门槛是本次小范围优化的项目建议，不是厂商指标或完整外部时序签核。若不满足，不事后放宽门槛，也不扩大成复杂调度器：记录失败证据及原因，再调整同一小范围方案。

不优先提频、不取消按键消抖、不以减少声部或缩短钢琴包络换取数字指标。显示仍只消费副本；在像素停钟/复位时音频通路应继续独立运行。

```text

  examples/    板键ADSR、旧渐变及独立双音色演示
```

| 旧位置 | 新位置/处理 |

| `fpga_project/uart_piano`、`uart_basic`、`display_rgb` | `projects/piano`、`uart_basic`、`display` |
| `fpga_project/instruments_board` | `projects/examples/instruments_board` |
| `fpga_project/poly_adsr_check`、`instruments_check` | `projects/checks/`保留各自子目录 |
| `fpga_project`根ADSR/渐变工程及必要配置 | `projects/examples/adsr`；所有普通/自动构建模式继续可定位 |
| `fpga_project/legacy`及旧抽象时钟文件 | `projects/legacy`，注明不可混用的历史板级输出 |
| 四个队友目录 | 作为兄弟目录整体进入`upstream`，保持互相引用和所有文件内容 |
