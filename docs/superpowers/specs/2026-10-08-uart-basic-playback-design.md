# FPGA UART基础演奏版设计

日期：2026-10-08。状态：用户已批准设计／计划并选择直接实施；本地实现、验证与独立位流交付见 [验证记录](../../uart-basic-20261008.md)。本文保留设计合同，不代表实物验收。

## 1. 目标与范围

电脑发送演奏命令，FPGA实时生成四个独立声部，经现有板载DAC送到耳机；电脑不播放或推送PCM。保留KEY0复位、KEY1=C4、KEY2=E4，电脑音符与实体按键共同使用四个声部。

本版实现115200波特率UART收发、HELLO握手、NOTE_ON／NOTE_OFF、PANIC、STATUS?、电脑来源失联回收，以及上位机对固定音色设备的能力适配。

音色固定为现有正弦，保留编译期ADSR和保守混音增益：名义48kHz下起音96点、衰减24000点、保持6554/65536峰值、释放5760点，MIX_SHIFT=5。上位机当前发送velocity=100；串口接口接受0～127，0按松键处理。

本版不实现APPLY配置、16谐波、运行时ADSR、音量滑条、三种发声模式、颤音、13个外接按键、ADC旋钮或音效。不能宣告CONFIG能力，不能回复伪造的APPLIED回执。此版不是完整赛题交付。

## 2. 依据与板级目标

代码依据为当前 `rtl/instrument_adsr_top.v`、`voice_allocator.v`、`voice_bank_adsr.v`、`synth_top.v`，PC依据为 `fpga_music_tool/STUDIO_PROTOCOL.md`、`studio_transport.py` 和 `studio.py`。现有分配器优先复用同来源，其次复用同音；上位机所有音符却使用source=0，不能未经转换直接连接。

板级依据：用户提供的 `Tang_Mega_NEO_Dock-60K_31004_Schematics (1).pdf`，Rev1.4、2025-03-31，第7／8页；核心板 `tang_mega_60k_30354_schematics..pdf` 第1／5／6页。底板PDF SHA256为 `5CA6049ED80BAB57BCAA87CC5E58926F569F2CA2AA11B984D52DA1782633F976`。本轮已读取并检查底板图像、核心板网络及电源文本，未实测电压或通信。

| 器件 | 当前工程GW5AT-LV60PG484AC1/I0，Device Version B |

## 3. 架构与回退

```text
PC固定音色演奏适配
  → UART RX同步／收字节 → 完整行解析 → PC事件队列 ┐
实体按键 → 同步／消抖 → 原事件编码器             ├→ 仲裁／来源取消
                                               └→ 四声部分配
                                                  → 原ADSR合成／混音
                                                  → 原B缓存／DAC输出
实际声部状态 → 回复格式化／发送队列 → UART TX → PC
```

拟新增 `uart_rx.v`、`uart_tx.v`、`uart_line_rx.v`、`uart_synth_protocol.v`、`uart_event_arbiter.v` 和 `instrument_uart_top.v`，每个模块写中文职责与时序注释。适当调整 `voice_allocator.v` 的可选行为与接口，但旧实例的默认声音和分配策略保持不变，不复制一套声部分配算法。

新工程放在 `fpga_project/uart_basic/`，顶层为instrument_uart_top，输出名instrument_uart；新增专用UART CST／SDC，不改变当前普通／自动工程的入口、约束或位流。实现后提供独立构建与测试入口；具体命令须按本机实际工具核对。当前未创建这些产品源码或工程。

## 4. UART与命令合同

UART为115200、8N1、无硬件流控，空闲高。RX先经过两级同步，再按系统时钟计数采样；50MHz整数位周期取434拍，在数据位中心采样并检查起始位、停止位。验证须覆盖不同起始相位、背靠背字节及±1%发送速度差，不把仿真当作模拟亚稳态证明。

ASCII以LF结束，接受CRLF。整行最多512字节，不含LF；字段只能在完整合法行结束后执行，数字累加必须检测溢出。超长行、非法字符、帧错误或字节丢失使该行作废，丢弃至下一个LF恢复；收半行后连续250ms无新字节则清除半行，后续重新组行。错误行不得产生音符。

命令名区分大小写，分隔符为ASCII空格，允许连续空格及首尾空格；整数仅允许十进制数字、最多10位，不接受正负号、小数或指数。除CRLF外不接受控制字符。上电时PC会话未建立；HELLO之前或会话超时后，音符命令回复ERROR 0 NOT_READY。STATUS?仍可查询，PANIC仍可安全释放，但二者不能重建会话。

| 命令 | 行为 |
|---|---|
| HELLO | 建立／重建PC会话，清除旧PC待执行事件并释放旧PC声部；回复真实能力，统计不重置 |
| NOTE_ON note velocity source | note与velocity为0～127，本版source仅支持0；非零velocity触发，0等价NOTE_OFF |
| NOTE_OFF note source | 仅释放对应PC音符，不按音符跨来源兜底；对未占用音符松键是无声部变化的合法命令 |
| PANIC | 清除此前待执行PC音符，并在采样边界释放所有PC拥有的声部；不复位实体按键或整个合成器 |
| STATUS? | 回复实际占用数、启动以来峰值、抢占次数和名义采样率；包括释放尾音 |
| APPLY及其他未支持命令 | 拒绝，保留现有固定配置；合法APPLY序号可识别时回复ERROR sequence UNSUPPORTED，否则ERROR 0 UNSUPPORTED |

握手回复为：

```text
SYNTH/1 CAPS=NOTES,STATUS MAX_VOICES=4 SAMPLE_RATE=48000 FW=uart-basic-v1 TONE=FIXED_SINE
```

FW是本版标识，不替代构建哈希；MAX_VOICES是可分配声部数，SAMPLE_RATE是名义值。HELLO回包须满足PC现有1800ms等待条件，但是否实物满足需要测量。

STATUS格式沿用现有协议。命令数量／格式错误回复ERROR 0 BAD_CMD，数值或source超范围回复ERROR 0 RANGE，队列拒绝回复ERROR 0 BUSY；诊断回包拥塞按下一节处理。NOTE_ON／NOTE_OFF无逐条成功回包，不能在PC记录中把“已发送”描述为“设备已执行”。

## 5. 来源、队列与停止

- 内部来源号在UART实例扩为8位：实体按键沿用0和1，PC为 `{1'b1,note[6:0]}`。这样同一电脑音符可重触发，不同电脑音符可同时占用独立声部。本版只接受外部source=0，其他来源拓展不在范围内。
- UART实例关闭跨来源的“同音复用”；两个不同输入演奏同一音高也独立分配。旧实例保留默认同音策略。同来源重触发、空闲→释放中→最老活动声部的分配及旧松键保护继续保留。
- 共用分配器增加受控的来源取消接口：取消请求使用valid／ready握手和来源mask／value；UART取消条件为来源最高位等于1。旧实例显式禁用／接零。取消时清gate和trigger，保留active及尾音，直到真实release_done回收，不伪造空闲状态。
- 仲裁器接到取消后，停止向分配器提交新事件，等待其空闲，在下一sample_request边界原子取消PC来源；期间保存实体事件。取消之前的PC排队事件作废，之后的PC事件等取消完成再执行，不能重新播放被取消的旧NOTE_ON。
- 两来源正常事件按轮转仲裁，队头valid且ready时才出队；未握手时字段必须稳定，只向选中的生产者返回ready。紧急取消优先，不让诊断发送阻塞演奏。
- 采用64字节RX队列、16条PC音符队列和4条回复描述队列。解析与TX并行，不等待一条回复发完才接收下一命令；持续数据速率及实际最坏服务间隔须通过测试核实，有限队列不作无限保序承诺。
- RX溢出使当前行作废并启动PC取消；PC音符队列溢出时拒绝当前命令，清除旧PC队列并取消PC声部，恢复后须重新发音。不能静默丢失NOTE_OFF导致卡音。实体编码器原有长期背压限制不宣称已修复。
- 重复STATUS?在回复拥塞时合并为最新快照，重复HELLO可合并；4条回复描述中保留1条握手位置，握手优先选取，但不打断正在发送的整行。错误洪泛可合并／丢弃诊断回包，但错误不得修改声音状态，不以无限TX缓存解决请求与回复速率差。

默认失联阈值3秒：每条合法HELLO、STATUS?、音符或PANIC命令更新PC保活；非法命令不能保活。PC现有每秒STATUS?轮询保留。超时只取消PC声部，实体按键继续使用；下次合法HELLO恢复PC会话。超时后的非HELLO命令不恢复演奏，避免旧残留数据重启声音。

PANIC与失联回收是“进入固定120ms释放”，不是立即将整个音频归零。因此PANIC后的STATUS占用数可以暂时非零，尾音结束才归零。KEY0则仍复位全部状态。只读状态必须从FPGA真实寄存器快照取值；32位抢占计数按现有位宽回绕。

## 6. 上位机最小改动

仅修改演奏能力判断、提示文字及相应测试，不更换界面或协议：

- 收到NOTES＋STATUS、没有CONFIG且TONE=FIXED_SINE时，允许直接演奏和四音和弦，不要求session.applied。
- 仍禁用“应用到设备”，明确显示“设备使用固定正弦音色，界面参数尚未应用”。草稿编辑、JSON和波表导出可以继续使用，但不能暗示影响硬件。
- CONFIG模拟设备仍按原规则先应用配置；不为固定音色设备制造一个虚假的applied对象。
- 断开前尽力发送PANIC，断开／重连清除PC按键状态。硬件3秒看门狗是独立兜底，不能依赖电脑关闭流程一定执行。
- 音符发送仅表示发送；真实统计来自STATUS，不用界面自算声部数冒充设备结果。

## 7. 验证与验收

以下是计划，不是已通过结果：

1. UART单元：空闲、全部256字节、不同起始相位／发送速率、背靠背字节、坏停止位、复位在起始／数据／停止阶段，以及TX忙时valid／ready稳定性。
2. 解析与队列：LF／CRLF、分片、512／513字节、缺字段／多字段、数字越界／溢出、非法字符、半行超时、连续命令、队列满／恢复、诊断洪泛，不执行半条命令。
3. 音符与来源：PC四个不同音符、同音重触发、第五音抢占、旧音松键、velocity=0、实体／PC同音并存、PANIC与物理键并发、取消后旧队列不复活、3秒超时及HELLO恢复。
4. 联合输出：首帧静音、KEY0中途复位、正常持续演奏不缺样本、释放尾音结束、串行左右声道逐样本校验；沿用A→B的R3有效／R4缓存与下一帧输出合同。
5. PC：固定音色设备可弹不可APPLY、CONFIG模拟设备原行为不变、错误握手／断连／重连状态正确；回归现有PC测试和全部RTL测试，不放宽断言。
6. 负向控制：局部故意破坏UART校验、来源映射或取消行为，至少一项相关自检必须失败；恢复正确源码再跑。
7. 实现：实际工具版本、源码／约束／位流哈希、资源、约束覆盖、Setup／Hold、UART同步例外及已有PR1014／外部DAC风险一起记录。没有完整约束不宣称时序通过。
8. 实物：先验证HELLO／STATUS，再耳机低音量测试单音、四音、松键、PANIC、拔线后的释放及实体键独立性；记录实际COM号和位流版本。没有上板数据不勾选比赛验收或整机延迟。

最小成功现象：上位机显示真实设备已确认；参数应用禁用；电脑琴键和四音和弦可经FPGA发声，松键有尾音；停止／断连不影响未被正常声部抢占的实体按键；复位清除全部声音。此行为须由后续测试证据确认。
